# 3.2  Code Signing Abuse
*Part 3: Encryption, Certificates and Fingerprinting*

ATT&CK: https://attack.mitre.org/techniques/T1553/002/

```
attack-technique:T1553
```

## Hunts

Every file signed by a certificate you know is compromised:

```
cert-thumbprint:<SHA256_THUMBPRINT>
cert-serial:"<serial>"
```

By subject or issuer, bad files only:

```
cert-subject-name:"<Company>" classification:[malicious, suspicious]
cert-issuer-name:"<CA name>" classification:[malicious, suspicious]
```

The `certificate` group keyword searches issuer and subject name, organization and unit together:

```
certificate:"*<Company>*" classification:malicious
```

Files signed after a certificate was revoked or leaked (set the date to the leak date):

```
cert-serial:"<serial>" signer-valid-from:[2022-03-01T00:00:00Z TO *]
```

Very short validity windows, which often mark throwaway certificates. This is a heuristic. Use a narrow `signer-valid-from` window to start:

```
signer-valid-from:[2026-11-01T00:00:00Z TO *] classification:[malicious, suspicious]
```

Impersonation of a trusted publisher. Files that claim a big vendor but are not clean:

```
cert-subject-org:"microsoft corporation" classification:[malicious, suspicious]
pe-company-name:"Microsoft Corporation" classification:[malicious, suspicious] NOT cert-subject-org:"microsoft corporation"
```

Packers signed via Taggant:

```
taggant-name:* taggant-valid-from:[2026-01-01T00:00:00Z TO *]
```

Certificate country, such as signers in a country that does not match the publisher:

```
certificate-country:[<CC>] classification:malicious
```

## Signatures

| **Hunt** | **Analyze query** |
|---|---|
| Leaked or stolen certificate after the leak date | `cert-serial:"<serial>" signer-valid-from:[2022-03-01T00:00:00Z TO *]` |
| Files signed as Microsoft but flagged | `cert-subject-name:"Microsoft Corporation" p:5+ firstseen:2022-01-01T00:00:00Z+` |

## Short-lived certificates

Certificates valid for about a week. Analyze cannot subtract two dates, so pick a window and keep both ends inside it. This example looks for certificates issued in the first week of a month that expired within two weeks of it. Slide the window to cover the period you care about:

```
signer-valid-from:[2026-11-01T00:00:00Z TO 2026-11-07T23:59:59Z] signer-valid-to:[2026-11-01T00:00:00Z TO 2026-11-14T23:59:59Z] classification:[malicious, suspicious, unknown]
```

Same, excluding Microsoft-signed files:

```
signer-valid-from:[2026-11-01T00:00:00Z TO 2026-11-07T23:59:59Z] signer-valid-to:[2026-11-01T00:00:00Z TO 2026-11-14T23:59:59Z] NOT cert-subject-org:"microsoft corporation"
```

Fake installers: signed, executable, impersonating popular software:

```
pe-product-name:*Teams* NOT cert-subject-org:"microsoft corporation" classification:[malicious, suspicious, unknown]
```

The same impersonation by file name:

```
filename:[*teams*setup*,*teams*install*,*msteams*] NOT cert-subject-org:"microsoft corporation" classification:[malicious, suspicious]
```

The campaign by name. The family name is free text, so confirm it:

```
threatname:[*Oyster*,*Broomstick*]
```

Low prevalence: a file seen only recently or only a few times:

```
signer-valid-from:[2026-11-01T00:00:00Z TO *] firstseen:7d- submissions:[* TO 3] classification:unknown
```

ATT&CK mapping:

```
attack-technique:T1204
```

## Cert Graveyard certificates

By thumbprint (SHA256; the CSV `CRThumbprint` column):

```
cert-thumbprint:<THUMBPRINT>
```

By signer name, when only the name is known:

```
cert-subject-name:"<CRSigner>" classification:[malicious, suspicious]
```

Serial and signer together. This is the Analyze version of `CertSerialMatchesCertReport == TRUE`:

```
cert-subject-name:"<CRSigner>" cert-serial:"<serial>"
```

Issuer, if the report names a rogue or unusual one:

```
cert-issuer-name:"<CRIssuer>" classification:[malicious, suspicious]
```

Validity window from the CSV (`CRValidFrom`, `CRValidTo`):

```
cert-subject-name:"<CRSigner>" signer-valid-from:[2024-01-01T00:00:00Z TO *]
```

## Retrosigned drivers

Drivers signed with a certificate that has expired. These are the artifacts that need the clock trick:

```
filename:*.sys signer-valid-to:[* TO 2026-11-18T00:00:00Z] classification:[malicious, suspicious, unknown]
```

Drivers whose certificate expired years ago:

```
filename:*.sys signer-valid-to:[* TO 2020-01-01T00:00:00Z] classification:[malicious, suspicious, unknown]
```

Drivers by detection name:

```
threatname:*.Hacktool.* filename:*.sys
```

Known abused drivers and rootkits:

```
threatname:*.Rootkit.* filename:*.sys
```

Drivers that are signed but unclassified (triage):

```
filename:*.sys cert-subject-name:* classification:unknown
```

Samples mapped to the technique:

```
attack-technique:[T1553, T1562]
```

## Signed and unsigned files

Signed files (the file carries a certificate):

```
cert-subject-name:*
```

Signed by a specific publisher:

```
cert-subject-org:"<publisher>"
```

Executables that carry no certificate. This is a heuristic, because Analyze may not record every certificate:

```
type:PE/* NOT cert-subject-name:*
```

Unsigned and not yet classified (the triage version):

```
type:PE/* NOT cert-subject-name:* classification:unknown
```

Signed but not clean (the `Signed/Untrusted` idea, by verdict):

```
cert-subject-name:* classification:[malicious, suspicious]
```

Signed with a certificate that has since expired:

```
cert-subject-name:* signer-valid-to:[* TO 2026-11-18T00:00:00Z] classification:[malicious, suspicious]
```

A single hash. The results page shows the certificate fields for it:

```
hashes:[<sha1>]
```
